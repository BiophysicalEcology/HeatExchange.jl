Parameters ​

The traits of an organism and the properties of its environment are held in structs, one for each process. This page lists them with their default values, and describes the functions that build ready-made sets.

Traits ​

A HeatExchangeTraits holds one of each of the structs below, and is built by position or, more conveniently, with one of the example_ functions:

julia
using HeatExchange, BiophysicalGeometry, Unitful

shape = Ellipsoid(65.0u"kg", 1000.0u"kg/m^3", 1.1, 1.1)
traits = example_heat_exchange_traits(; shape_pars = shape,
    radiation_pars = example_radiation_pars(; body_absorptivity_dorsal = 0.9),
    evaporation_pars = example_evaporation_pars(; skin_wetness = 0.01))
organism = Organism(Body(shape, Naked()), traits)
radiation_pars(organism).body_absorptivity_dorsal
0.9

Each group is read back from an organism or a set of traits by a function of the same name as its field: insulation_pars, conduction_pars_external, conduction_pars_internal, radiation_pars, convection_pars, evaporation_pars, hydraulic_pars, respiration_pars, metabolism_pars and options.

The defaults shown below are those of the structs themselves.

Example sets ​

Two sets of functions return parameters ready for use, each taking keywords for the values to change.

Those named example_… are the defaults of the NicheMapR endotherm model endoR: a 65 kg ellipsoid with 2 mm of fur and a core at 37 °C, in still, dry air with the sky and ground at air temperature and no sun (Kearney et al. 2021).

Those named example_ectotherm_… are the defaults of the NicheMapR ectotherm model: a 40 g lizard with a tenth of its surface on the ground and a skin that is 0.1 % wet (Kearney and Porter 2020).

Bounds, and fitting ​

Each parameter is a functional trait in the sense of Kearney et al. (2021), see Units, dimensions and functional traits.

The default value of each field is a Param of ModelParameters.jl, which carries a value with its units and, for many fields, bounds:

julia
RadiationParameters().sky_view_factor
ModelParameters.Param{Float64, @NamedTuple{val::Float64, bounds::Tuple{Float64, Float64}}}((val = 0.5, bounds = (0.0, 1.0)))

A model built from structs of Params can be shown as a table, and its parameters read and set as a vector, which is what a sensitivity analysis or an optimiser needs. The bounds are those within which a trait makes physical sense. The solvers remove the wrappers before they compute, so plain numbers and quantities work as well, and the example_ functions return them.
